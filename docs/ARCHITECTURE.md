# GeoStruct 架构说明

## 1. 设计目标

GeoStruct 的目标不是把一张几何题照片直接变成“必然正确的答案”，而是把不可控的视觉识别拆成可观察、可修正的几个阶段：

1. 从原图保留足够像素并选择真正的几何区域；
2. 用轻量模型区分图元像素；
3. 用确定性算法生成点、线、曲线和连接候选；
4. 在有可靠题干模板时用显式约束过滤候选；
5. 把不确定结果交给用户校正；
6. 输出带来源、置信度和不确定性的结构化文档。

核心原则是：感知误差不能被悄悄升级为几何事实。

## 3. 坐标与缩放

本项目曾出现过“加入放大功能后识别点线全部压缩到一小块”的回归。根因不是模型阈值，而是显示坐标、旋转坐标、源图裁剪坐标和识别坐标混用。

当前明确区分四套坐标：

| 坐标系 | 用途 |
| --- | --- |
| 原始图像坐标 | 保留拍照得到的真实像素 |
| 旋转后源画布坐标 | 在同一方向下完成选区裁剪 |
| 模型坐标 | 固定 320×320 的 U-Net 输入与输出 |
| 校正画布坐标 | 用户看到和编辑的逻辑坐标 |

CSS zoom 只改变显示，不改变模型输入。识别时从已旋转的源分辨率画布裁剪选区，然后把模型结果一次映射回校正画布。点柄、标签、线宽和命中半径再乘以显示缩放的倒数，所以原图放大后覆盖层的屏幕尺寸保持稳定。

tests/semantics-smoke.ts 保留了大选区归一化、小选区放大和 100%/200% 坐标一致性回归。

## 4. 模型

GeometryUNet 是一个紧凑的编码器—解码器：

| 阶段 | 通道 |
| --- | ---: |
| enc1 | 3 → 24 |
| enc2 | 24 → 48 |
| enc3 | 48 → 96 |
| bottleneck | 96 → 160 |
| dec3 | 160+96 → 96 |
| dec2 | 96+48 → 48 |
| dec1 | 48+24 → 24 |
| head | 24 → 6 |

每个 Block 由 3×3 投影卷积和残差式深度可分离卷积组成，编码端使用最大池化，解码端使用双线性插值与 skip connection。输出是 B×6×H×W logits。

六类标签：

0. background
1. solid_line
2. dashed_line
3. circle_or_ellipse
4. point
5. text

浏览器模型固定输入 1×3×320×320，输出 1×6×320×320。预处理仅把 RGB 像素缩放到 0–1；后处理执行逐像素 argmax。

## 5. 从掩码到图

Python 评估链和浏览器链都遵循“先分割、后结构化”，但具体实现不同：

- ml/extract_graph.py 用点类连通域形成点候选，在点对之间采样线类支持率，构造掩码派生拓扑；
- app/mobileQuestionConstraints.ts 从点类掩码提取并合并候选，计算膨胀线掩码支持和有序共线性；
- app/vision.ts 提供通用回退，包含二值化、线候选、交点、箭头尖端、圆和标签框候选；
- deriveAttachments 不再要求固定度数，而是用几何共线性和已有完整/部分线段恢复“点在线段上”的候选，并保留用户之前确认的等分选择。

箭头不是 U-Net 的独立类别。它来自保守的线方向后处理，未确认箭头不会进入最终 rays。

## 6. 题干约束

题干只在本地帮助候选过滤。当前代码不会把任意中文题干自动解析成完整几何逻辑，而是提供一个严格的已知图2模板：

- templateFromQuestion 需要多个独立短语同时命中；
- 模板声明 A–G、10 条线和 C–D–G、B–F–C、E–F–D、A–D–B 等有序共线关系；
- beam search 把 U-Net 候选分配给角色；
- 评分同时使用点置信度、模板线支持和有序共线性；
- 未命中模板时返回 null，调用方进入通用回退。

因此图2中的点名来源是 question_constrained，而不是 OCR。模板不能静默套用到不相关题目。

公开网页按钮使用的是浏览器内自绘并人工核对的结构夹具，打开即载入 7/10/0/4，目的是演示校正和分享交互；它不计入模型识别结果。真实照片模型回归需要在本地显式提供图片和有权使用的 ONNX 权重。

## 7. 人在回路的数据语义

每个点和线记录 source：

- detected：机器候选；
- question_constrained：题干模板约束后的候选；
- manual：用户创建或确认。

线内位置分两类：

- approximate：只知道点在线上，大致比例与坐标不确定；
- division：用户明确选择 m 等分中的第 n 个分点。

导出时只有 division 会变成 user_confirmed_division，并标记 exact=true。近似位置会明确写出 coordinateUncertain 和 ratioUncertain，禁止接收方把它当作中点或精确比例。

同理，只有人工创建或显式确认的箭头/圆进入 primitives.rays 和 primitives.circles；未确认候选进入 excludedUnconfirmedCandidates。

## 8. geometry-diagram/v5

v5 文档包含：

- points 及视觉坐标、归一化坐标、来源；
- segments、rays、circles；
- collinearChains；
- attachments；
- 未确认候选隔离清单；
- drawingContract 必画线清单；
- uncertainties；
- 给多模态模型的核对顺序。

坐标只用于相对布局，不得用于推断长度、角度、比例、垂直或平行。

题干默认不在 JSON 中重复。接收方被要求从随附原题图片读取印刷题干，遵循以下权威顺序：

1. 原题图片中的印刷题干；
2. 多模态模型对图形的直接观察；
3. 用户校正或机器识别的辅助结构。

如果辅助结构与题干冲突，必须报告冲突并以题干为依据。

## 9. 运行时与隐私边界

生产页面的识别在浏览器内完成：

- Windows/兼容 Android 浏览器优先尝试 WebGPU；
- 不可用时使用 WASM；
- iPhone/iPad Safari 走单线程 WASM；
- 当使用者自行放置有权使用的 ONNX 工件时，模型作为同源静态资源加载；公开仓库默认不分发 PGDP5K 衍生权重，模型缺失或加载失败时明确降级为低置信度传统视觉候选；
- ONNX Runtime 1.27.0 的平台文件从固定版本 CDN 按需加载；
- 题图像素不发送到 CDN、PC CUDA 服务或其他推理 API。

ml/serve.py 与 scripts/start_gpu_inference.ps1 保留为本机 CUDA 诊断工具，生产 Web 页面不依赖它们。

## 10. 验收层级

项目把验收分成四层，避免用一个好看的数字掩盖其他失败：

| 层级 | 验证内容 | 当前证据 |
| --- | --- | --- |
| 像素层 | 六分类混淆矩阵、IoU、P/R | 1,000 张 PGDP5K 测试图 |
| 拓扑代理层 | 点匹配、连接边、完整图 | 从预测/真值掩码派生；不是原始关系直评 |
| 语义回归层 | 箭头、attachments、编辑保留、v5 规则 | tests/semantics-smoke.ts |
| 产品案例层 | 图2的 7/10/0/4 与 E–G | 题干模板约束案例；不代表通用准确率 |

下一步最重要的是加入原始关系标注或人工图审计层，直接评价最终结构，而不是继续只优化背景占比很高的像素准确率。
